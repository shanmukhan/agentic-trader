## 6. Automated Trading Architecture

Design the application for eventual fully automated trading, but keep actual execution disabled during this modernization.

Use a modular pipeline:

Market Data → Data Validation → Stock Screening → Strategy Signals → Portfolio Construction → Risk Validation → Order Proposal → Paper Execution → Portfolio Accounting → Monitoring

The architecture must distinguish:

- Research recommendations
- Strategy-generated signals
- Approved investment decisions
- Submitted orders
- Executed fills
- Portfolio holdings

A signal must never automatically bypass risk controls.

Implement safeguards for:

- Maximum position size
- Maximum portfolio exposure
- Available cash
- Concentration limits
- Duplicate orders
- Stale market data
- API failures
- Unexpected application restarts
- Exchange trading sessions
- Market holidays
- Corporate actions
- Emergency kill switch

Use durable order states, idempotency, and reconciliation.

For now, all execution must remain paper-only.

Do not create, enable, or submit real-money orders.
