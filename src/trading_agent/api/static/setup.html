Three different credentials

  • Operator token: unlocks this local app. It is generated locally.
  • Kite request token: returned after Zerodha login; single use, valid for only a few minutes.
  • Kite access token: obtained by exchange and used only by the server for market data; expires daily.

These steps do not place orders, arm automation, deposit money or clear trading safeguards. This setup is for manual paper accounts. Keep the server on loopback and use a trusted personal computer.

1. Register your Kite app

Create an app and choose market-data access in Kite’s developer console. App registration, subscription payment, Zerodha login and 2FA stay on Zerodha’s website.

Postback URL is not needed. The free Personal plan does not include live quotes. Confirm current charges before buying a data subscription.

2. Save app credentials privately

Leave this step alone if credentials are already configured. Saving replacements clears the stored access token. Secrets are stored in a private file beside this account’s database. Status hides credential values; the public API key appears in the broker login URL, while the secret and access token are never returned.

3. Sign in to Zerodha

Disconnect the feed before replacing a session. Open the login window, complete login and 2FA, then return here. With the redirect URL above, the request token is captured into the field below. If capture is unavailable, copy only the request_token value from the redirect address.

No access token needs copying into .env after a UI exchange. The saved session is used by this manual account on reconnect/restart. A saved token can still be expired; check it before connecting.

4. Download the NSE catalog and select symbols

Disconnect before catalog or selection changes. Existing mappings are never silently replaced. Selection must include every held symbol; resolve pending orders before changing it.

A catalog EQ row can be an ETF. Current cost estimates assume equity shares; ETF-specific fees are not validated. Subscription alone does not approve an instrument for paper execution.

5. Add a reviewed exchange session

Review NSE holidays and notices before adding a date. No weekday, holiday roll-forward or market opening is assumed. Existing definitions cannot be changed here. Supported hours are within 09:15–15:30 IST.

Long-term corporate-action/price-basis reviews are a separate per-symbol step in the trading console. This calendar form does not clear them.

6. Connect the read-only feed

Connection requested is not proof of fresh usable quotes. Check readiness in the trading console. Reconnecting can resume pending fills and protective exits; review the confirmation. Disconnecting does not close holdings: fills and exits require a working feed. No automatic retry is performed by these setup buttons; the streaming worker retains its bounded reconnect policy.
